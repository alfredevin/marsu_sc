PART 1: SYSTEM ARCHITECTURE & MODULE SCOPE OVERVIEW

This engineering specification details the complete relational database design for the first three (3) sub-modules of the MarSU Retention System (ISREMS): (1) Student Information Management, (2) Academic Monitoring, and (3) Attendance and Engagement Monitoring. While the centralized ERP core supplies reference tables, twenty-one (21) specialized normalized tables are required to store student demographic vulnerability risk variables, electronic class records, raw and transmuted assessment scores, roll-call sessions, compliance telemetry, and scholastic deficiencies.

PART 4: RELATIONAL INTEGRITY & FOREIGN KEY ARCHITECTURE

All 21 ISREMS retention tables strictly interconnect with baseline core tables using non-destructive Foreign Key constraints. Foreign keys referencing students.student_number enforce ON DELETE CASCADE to preserve referential consistency, while links to employees.id and users.id utilize ON DELETE SET NULL to preserve academic audit histories.
